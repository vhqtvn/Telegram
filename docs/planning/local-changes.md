## Fork product identity
- applicationId: `vn.vhn.telegram` (debug `.beta`, standalone `.web`) via `APP_PACKAGE` in `gradle.properties`; java package/namespace stays `org.telegram.messenger` (no code move).
- api_id/api_hash: put `TELEGRAM_API_ID` / `TELEGRAM_API_HASH` in `local.properties` (gitignored); `:TMessagesProj:patchBuildVars` injects them into BuildVars.java at build time and restores the committed placeholders when the build ends. The committed `APP_ID = 4` / `APP_HASH` placeholders stay in the tree.
- keystore/signing: signing values resolve in three tiers — gradle properties first (non-dummy), then the optional gitignored `.local/config/android-keys/signing.properties`, then committed dummies (`android`/`androidkey` + `TMessagesProj/config/release.keystore`). signing.properties keys: `RELEASE_STORE_FILE` (root-relative or absolute), `RELEASE_STORE_PASSWORD`, `RELEASE_KEY_ALIAS`, `RELEASE_KEY_PASSWORD`, plus `RELEASE_STORE_PASSWORD_FILE` / `RELEASE_KEY_PASSWORD_FILE` (file whose trimmed content is the password — operator layout: `.local/config/android-keys/.password`). Operator keystore: `.local/config/android-keys/release.keystore`, alias `telegram-fold`; both `RELEASE_STORE_PASSWORD_FILE` and `RELEASE_KEY_PASSWORD_FILE` point at the same `.password` file (operator-chosen single-password layout — the green signed release build confirms the layout works; not a claim about keystore internals). Real keystores/passwords stay under gitignored `.local/` — NEVER committed.
- product name: `VHGram` / `VHGram Beta` (`AppName`/`AppNameBeta` in `TMessagesProj/src/main/res/values/strings.xml`). Launcher icon is still upstream's Telegram icon — MUST be replaced before any store distribution (Telegram ToS §2.4 forbids official-logo reuse). Localized `AppName` overrides in `values-*/strings.xml` (ru/de/es/it/ko/nl/ar/pt-rBR/uk, ~10 locales) still say "Telegram" and shadow the label on those device locales — follow-up surface.
- registration: a `vn.vhn.telegram` api_id/api_hash pair must be obtained from https://my.telegram.org and used with the same account-type (`vn.vhn.telegram`, auth.xml + ContactsController).
- stability: `MainThreadWatchdog` (fork-only, supersedes `ResumeWatchdog`) continuously monitors main-thread liveness: a front-of-queue canary posted every `CHECK_INTERVAL_MS` (3s); `MISSES_TO_KILL` (5) consecutive misses = ~15s true starvation → capture main stack + thread census → self-kill → clean Android relaunch in seconds. Covers the Samsung OneUI freezer/vsync hang (bugreport-confirmed on this fork; official Telegram affected too) INCLUDING the thaw path where main is starved before any lifecycle message is deliverable (resume-armed arming was structurally blind to that; splash is NOT_FOCUSABLE so no ANR ever fires). Threshold knobs = `CHECK_INTERVAL_MS` × `MISSES_TO_KILL` (3s × 5 = 15s) constants in the fork-owned class. Debug builds are freezer-exempt — why debug never hangs.

## Maintenance rules (binding)
- R1: Inline surgical patches only for state/correctness fixes in historically stable regions (verify stability via `git log -L` before choosing inline).
- R2: All GROWING policy logic (breakpoints, pane policy, posture hooks) lives in a fork-owned helper class (planned: `org.telegram.messenger.FoldableConfig`, static, dependency-light, Java, Telegram idiom — introduced at FOLD-002, NOT retrofitted onto iteration 1). Upstream files get one-line call sites; fork-owned file paths cannot conflict with upstream by construction.
- R3: Rebase-per-release: rebase the local themed commit series onto each new upstream "update to" commit; NEVER squash local commits into the upstream base; keep commits themed with `foldables:` prefix (other themes allowed as they appear); one conceptual change per commit.
- R4: This registry is updated at every release bump (new base hash) and at every local commit landing.
- R5: Post-bump verification gate: `./gradlew :TMessagesProj:compileDebugJavaWithJavac` then `./gradlew :TMessagesProj_App:assembleAfatDebug` (env: JAVA_HOME=~jdk/jdk-21*, PATH prepend ~/android-sdk/cmake/3.22.1/bin); fold-matrix smoke when hardware available; `apkdiff.py` is valid ONLY for own-vs-own regression diffing (fork-vs-official byte comparison is impossible once any local change lands — dex differs).

## Release-bump runbook
1. `git fetch upstream`
2. Find target: `git log upstream/master --grep="update to" --oneline -5`
3. `git rebase <new-release-hash>` (resolve conflicts per local commit, guided by the entries below)
4. Run verification gate (R5)
5. Update this file: new base hash + any notes from conflict resolution
6. Operator pushes: `git push origin HEAD --force-with-lease` (rebase rewrites SHAs)
